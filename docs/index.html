How to read this page

Every one of the twenty-six levels is laid out the same way, so once you know the shape of one level you know them all:

  • The problem — Cryptopals' official wording and the fixed input vector.
  • The idea — the single concept the level is really testing.
  • The code — the actual solve from this crate. The shared helpers it calls are in a collapsible supporting code panel, quoted from src/util/.
  • Worked example — a few real bytes, by hand, so you can watch it happen.
  • Official I/O — the exact inputs and outputs the tests assert against.

The library is src/lib.rs; the challenges live in src/sets/set1/ through src/sets/set4/ and the reusable helpers in src/util/. The test suite is the definition of "done".

  • The trusted gate (fmt + test + clippy) is just gate. Run one level's own tests with just lvl set1 l003.
  • L1–L6 are hand-rolled in src/util/ on raw bytes. L7 pulls in the aes crate for AES-128 itself; L8 just reuses util::hex.

The building blocks

Eleven small modules in src/util/ carry almost all of the work; each solve is then mostly glue. All of them operate on raw bytes or 32-bit words: hex and base64 are only transport.

The error type

Every solve either returns its answer or a single shared CpalError; seventeen variants, one per distinct failure mode the levels actually produce, in src/util/err.rs. New variants are added just-in-time as a level needs them.

Source

One Rust crate. The library is src/lib.rs — just pub mod sets and pub mod util. Each level is a small module under src/sets/set1/, src/sets/set2/, src/sets/set3/ or src/sets/set4/ exposing a solve function and a #[cfg(test)] module with its own tests (unit and proptest property oracles). Shared primitives live in src/util/. The official challenge payloads ship under data/challenge_04.txt, data/challenge_06.txt, data/challenge_07.txt, data/challenge_08.txt and data/challenge_10.txt. Re-run everything — format, tests and clippy — with just gate.
